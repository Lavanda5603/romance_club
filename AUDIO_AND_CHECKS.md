# Музыка, кнопки и проверка работы

Подключила `assets/audio/background_music.mp3` и `assets/audio/button_click.mp3`. Оба файла оставляю в MP3. Общая музыка повторяется и не начинается заново при переходе между экранами. Щелчки играют отдельно.

Настройки сразу меняют громкость. «сохранить» записывает её в файл. При выходе без сохранения возвращаю прежние значения. Ноль выключает соответствующий звук. Сворачивание ставит музыку на паузу, возврат продолжает её.

Кнопки озвучиваю в обработчиках, включая Enter и выбор пунктов. Отключённые кнопки и движение ползунка не щёлкают. Ошибка проигрывателя не блокирует действие кнопки.

## Проверка на Android

Нативный тест находится в `integration_test/audio_test.dart`. Использую отдельное приложение с собственным хранилищем, чтобы тест настроек не менял основную копию:

```powershell
flutter test integration_test/audio_test.dart -d emulator-5554 --dart-define=ROMANCE_AUDIO_CHECK=true
```

У отдельной debug-сборки ID `com.example.romance_club.audio_check`. Обычная debug/release-сборка сохраняет `com.example.romance_club`. Флаг передаю только команде проверки.

После интеграционных тестов собираю обычный APK командой `flutter build apk --release`. В текущем Flutter `--no-pub` пропускает обновление регистратора плагинов при смене режима, поэтому после debug-теста этот флаг для release не использую.

Тест проверяет декодирование обоих MP3, движение позиции музыки, отдельный щелчок, переход в настоящий экран настроек, отключение громкости, запись настроек, паузу и продолжение. Прослушивание физических динамиков компьютера этим тестом не подтверждается.

При первом прогоне стандартная команда Flutter после ошибки установки автоматически удалила старую локальную копию на эмуляторе. Локальный вход потребуется выполнить заново. Серверные аккаунты, покупки и сохранения не удалялись. Для следующих прогонов использую отдельный пакет и проверяю его ID перед установкой.
