# Условия, баллы и переходы

## Как я задаю условие

В редакторе сцены есть поле «условие». Пустое поле разрешает показ сцены. Можно сравнивать любой счётчик с числом или другим счётчиком:

```text
points >= 5
friendship >= 3
romance_adrian > romance_cat
my_score = -2
flag:secret = true
friendship >= 5 И flag:met = true
(romance_adrian >= 10 ИЛИ romance_cat >= 10) И flag:secret != true
```

Поддерживаю `>`, `<`, `>=`, `<=`, `=`, `==`, `!=`. Для флага использую `=`, `==` или `!=` со значением `true`/`false`. «И» можно записать как `AND` или `&&`, «ИЛИ» — как `OR` или `||`. «И» выполняется раньше «ИЛИ»; для другого порядка ставлю скобки.

Имена счётчиков пишу латинскими буквами, цифрами и подчёркиванием; первый символ — буква или подчёркивание. Во флагах также поддерживаю русские буквы, например `flag:помог_дедушке=true`, чтобы использовать уже сохранённые флаги истории. Регистр имени имеет значение. Пока счётчику ничего не начислено, он равен 0; пока флаг не установлен, он равен false. Поэтому проверяю написание имени: `friendship` и `frendship` — разные счётчики.

Ошибку синтаксиса вижу при сохранении. Если некорректное условие уже попало в данные другим способом, игра показывает ошибку загрузки вместо открытия запрещённой ветки.

## Как я начисляю баллы

В действии выбора указываю имя счётчика и целое изменение: например, `friendship` и `2`, либо `romance_adrian` и `-1`. Могу создать свой счётчик, например `trust`. Новые счётчики тоже сохраняются и восстанавливаются. Общие баллы называются `points`.

Сначала применяются все баллы и флаги выбора, затем выполняется переход и проверяется условие целевой сцены.

## Как я настраиваю ветвление

1. В сцене нажимаю «Добавить условный переход».
2. Ввожу условие и выбираю целевую сцену.
3. Правила располагаю по приоритету: срабатывает первое выполненное. Кнопкой «Выше» поднимаю правило.
4. Если ни одно не выполнено, используется обычная «Следующая сцена». Если она не выбрана, это конец эпизода.
5. Сохраняю сцену, затем эпизод.

Например, сначала задаю `romance_adrian > romance_cat` → сцену Адриана, затем `romance_cat > romance_adrian` → сцену Кота. В обычной «Следующей сцене» выбираю ветку для равенства баллов. Пустое условие правила означает «всегда» — его ставлю последним.

Прежние правила эпизодов 4 и 5 перенесены в данные миграцией 026. Они доступны для изменения в редакторе. В игровом коде больше нет проверки конкретных ID 220/307. При равных положительных баллах сохранён прежний приоритет; при нулевых значениях используется прежняя ветка по умолчанию.

## Изменённые файлы этой доработки

- `lib/src/core/scene_condition.dart` — разбор, проверка и вычисление выражений.
- `lib/src/features/game/game_view_model.dart` — условия, правила переходов и восстановление произвольных счётчиков.
- `lib/screens/scene_editor_screen.dart` — редактор правил и ошибки условия.
- `lib/screens/action_editor_screen.dart` — проверка имени счётчика и количества баллов.
- `lib/screens/episode_editor_screen.dart` — проверка выражений перед сохранением всего эпизода.
- `lib/src/domain/models/episode_model.dart` — модель условного перехода.
- `lib/src/data/repositories/episode_repository_remote.dart` — преобразование правил между моделями и Protobuf.
- `protos/scene.proto`, `lib/generated/scene.pb.dart`, `lib/generated/scene.pbjson.dart` — контракт правил и сгенерированные модели.
- `server/src/main.rs`, `server/src/episode_store.rs`, `server/src/save_episode.surql` — чтение, проверка целей, сохранение и преобразование ключей правил.
- `server/migrations/025_scene_routes.surql` — поле правил в БД.
- `server/migrations/026_story_route_rules.surql` — перенос прежнего ветвления.
- `test/scene_condition_test.dart`, `test/scene_links_test.dart`, `server/src/episode_transaction_tests.rs` — проверки выражений, UI, прогресса, миграции и round-trip правил.
- `README.md`, `CONDITIONS_AND_ENDINGS.md` — инструкции.
