# Клуб романтики — Леди Баг и Супер-Кот

Я сделала мобильную визуальную новеллу на Dart и Flutter. В игре можно читать эпизоды, выбирать ответы и продолжать с сохранённой сцены. Ещё я добавила регистрацию, профиль, магазин и редактор, в котором можно менять сцены, фоны, персонажей и переходы.

## Что я сделала

- Подготовила пять эпизодов. Подобрала фоны и эмоции персонажей, настроила их положение и расположение текста.
- Доработала пятый эпизод: у признания Адриана теперь три разных реакции, которые сходятся в сцене поцелуя на мосту.
- В четвёртом и пятом эпизодах показала героев команды по очереди. У каждого свой кадр и спрайт, а имена в игре подписаны по-русски.
- Добавила иконку приложения и подготовила дневные, вечерние и пасмурные варианты фонов.

Сюжет, оформление сцен и загруженные картинки я сохраняю в SurrealDB. Последние доработки кода делала в ветке `pon`. В `main` собраны исправления по ревью и команды для запуска и переноса базы на SurrealDB 4.0.0. Чтобы получить мои настроенные эпизоды на другом компьютере, нужно отдельно восстановить дамп базы.

## Как устроен проект

Клиент написан на Flutter, сервер — на Rust. Приложение отправляет запросы серверу через gRPC, а сервер читает и сохраняет данные в SurrealDB. Контракты запросов и ответов описаны в `protos`.

Экраны лежат в `lib/screens`, логика прохождения — в `lib/src/features/game`, а код работы с сервером — в `lib/src/data`. Серверный код находится в `server/src`, миграции базы — в `server/migrations`, локальные картинки и звуки — в `assets`.

## Как я храню базу

Для локального запуска использую `romance_club/main`. Хранилище SurrealDB 4 находится в `database/local-v4`. Дамп версии 3 и подготовленную копию для переноса храню отдельно. При восстановлении сохраняю журнал миграций: сервер сверяет контрольные суммы, поэтому изменения схемы оформляю новыми миграциями.

Пароли и ключ приложения храню в локальном `server/.env`. Папку базы, дампы и ключи не добавляю в Git.

## Требования и подготовка

Нужны Flutter/Dart с ограничениями из `pubspec.yaml`, Rust stable ≥1.95,
`protoc`, SurrealDB 4.0.0 и Python ≥3.10. Python-пакеты устанавливать не нужно.
На Windows для сборки Rust/Flutter desktop нужны соответствующие MSVC Build Tools.
Для iPhone нужны macOS, Xcode и Apple Account.

Все команды выполняются из корня проекта:

```sh
flutter pub get
python3 tools/local_dev.py init
```

На Windows вместо последней команды:

```bat
setup-local.cmd
```

`init` создаёт `server/.env` из шаблона, заполняет пустые `SURREAL_PASS`
и `JWT_SECRET` случайными значениями, сохраняет непустые настройки.
Для существующей БД сначала укажите её реальные учётные данные.
Значения с пробелами заключайте в кавычки. Подстановка `$VARIABLE` не выполняется.

## Обычный запуск

Первый терминал — постоянная БД на `127.0.0.1:8000`:

```sh
./server/start-db.sh
```

На Windows:

```bat
start-database.cmd
```

Второй терминал — Rust-сервер:

```sh
./server/start-server.sh
```

На Windows:

```bat
start-server.cmd
```

При каждом запуске используется тот же `database/local-v4`, данные сохраняются
после остановки. Rust применяет новые миграции и готовит недостающие превью.
Остановка и повторный запуск этого хранилища проверены, числа записей сохранены.
Для телефона по Wi-Fi запускайте `./server/start-server.sh --lan` или
`start-server.cmd --lan`. gRPC будет слушать `0.0.0.0:50051`; порт БД остаётся
локальным. Разрешите входящий TCP 50051 в firewall. Телефон должен иметь
сетевой доступ к компьютеру.

## Переезд SurrealDB 3 → 4 на Windows и macOS

Используется экспорт/импорт в **новое хранилище**. Старый каталог данных
не открывается версией 4 и не преобразуется на месте. Сохраняйте его до
проверки новой базы. Установленная версия 4 не должна заменять единственную
копию старого бинарника, если экспорт ещё не сделан.

1. Остановите Rust-приложение, оставьте SurrealDB 3 работающей. В `server/.env`
   укажите логин/пароль, namespace и database исходной БД.
2. Экспортируйте отдельным бинарником версии 3:

```bat
export-database-v3.cmd "D:\backups\romance-v3.surql" --surreal "C:\Tools\surreal3\surreal.exe"
```

На macOS/Linux:

```sh
python3 tools/local_dev.py export-v3 database/imports/romance-v3.surql --surreal /path/to/surreal3
```

Скрипт требует CLI 3.x и не перезаписывает существующий файл. Используйте
аргумент файла, а не `>`: Windows PowerShell 5 может записать перенаправленный
текст в UTF-16.

3. Остановите SurrealDB 3. Установите CLI **4.0.0** отдельно. Запустите
   `start-database.cmd` или `./server/start-db.sh`: новое хранилище находится
   в `database/local-v4`. Учётные данные для нового экземпляра берутся из `.env`.
4. В другом терминале импортируйте файл или ZIP с единственным SQL-файлом
   в новую базу, например `restored_v4`:

```bat
import-database-v4.cmd "D:\backups\romance-v3.surql" --database restored_v4
```

```sh
python3 tools/local_dev.py import-v4 /path/to/backup.zip --database restored_v4
```

5. Успех обозначается `verified: true` и путём `manifest.json`. Сверяются числа
   записей всех таблиц с экспортом. Затем задайте `SURREAL_DATABASE=restored_v4`
   в `server/.env` и запускайте Rust-сервер.

Скрипт отказывается импортировать поверх базы с таблицами/доступами/функциями.
При ошибке частичный импорт сохраняется для диагностики; для следующей попытки
выберите новое имя базы. Подробности — в `database/imports/.../*.log`.
База приложения автоматически не удаляется. Параметры `--namespace`,
`--database`, `--endpoint` позволяют указать нужное окружение.

Общая Python-реализация используется обеими ОС: ZIP распаковывается без
использования путей его элементов; UTF-16 переводится в UTF-8; исходный SQL
сохраняется. Из определения `asset_delete_access` удаляются экспортированные
заглушки ключей, чтобы SurrealDB сгенерировала новые. Поддерживается экспорт
уровня базы без переключений `USE NS/DB` и изменений namespace/database.

Проверить текущую базу:

```sh
python3 tools/local_dev.py verify
```

На Windows используйте `py -3 tools\local_dev.py verify`.

## Телефон и установка на iPhone на 7 дней

Откройте `ios/Runner.xcworkspace` в Xcode. В `Settings → Accounts` добавьте
Apple Account. Для Runner в `Signing & Capabilities` включите автоматическую
подпись и Personal Team; при необходимости задайте уникальный Bundle ID.
На iPhone включите Developer Mode, доверие компьютеру и сертификату разработчика.

Подключите iPhone для первой установки. Узнайте IP компьютера: на Mac с Wi-Fi
`ipconfig getifaddr en0`, на Windows `ipconfig`. Затем:

```sh
flutter devices
flutter run --release -d DEVICE_ID --dart-define=GRPC_HOST=192.168.1.10
```

Замените пример IP адресом компьютера. После установки можно отключить кабель
и открывать приложение по иконке. Нужна release-сборка. Personal Team выдаёт
профиль до 7 дней с момента выдачи; после истечения приложение нужно
пересобрать и установить повторно. Это ограничение Apple.

Rust-сервер и БД всё равно должны работать и быть доступны телефону по сети.
Для работы вне этой сети нужен отдельно размещённый сервер с TLS и HTTP/2/gRPC.
Общие параметры сборки по умолчанию: `GRPC_HOST=localhost`, `GRPC_PORT=50051`,
`GRPC_TLS=false`. Для внешнего TLS endpoint обычно используют порт 443
и `GRPC_TLS=true`. Параметры меняются при пересборке, а не через hot reload.

Android-эмулятор: `--dart-define=GRPC_HOST=10.0.2.2`.
Android-телефон по USB: `adb reverse tcp:50051 tcp:50051`, затем запуск
с `localhost`. На физическом iPhone `localhost` означает сам телефон.
Flutter Web требует отдельного транспорта gRPC-Web.

## Проверки и их границы

```sh
flutter analyze
flutter test
python3 -m unittest discover -s tools -p test_local_dev.py -v
python3 tools/local_dev.py test
```

На Windows замените `python3` на `py -3`. Rust-тестам с `--include-ignored`
нужна запущенная SurrealDB на `127.0.0.1:8000` с учётными данными из `.env`.
Они создают отдельные временные базы и удаляют их после выполнения.
Обычный `cargo test --locked` пропускает 11 интеграционных тестов.

Проверены 164 Flutter-теста, 50 Rust-тестов с интеграционными сценариями на
SurrealDB 4.0.0 и Python-проверки подготовки импорта. Живыми запросами
Dart → Rust → восстановленная БД проверены регистрация/вход, чтение всех
эпизодов, сохранение/чтение/сброс прогресса, превью и изображение для игры.
Экспорт 3.3.5 → ZIP → импорт 4.0.0 проверен настоящими бинарниками этих версий;
попытка повторного импорта в заполненную базу отклонена.
Проверочный аккаунт удалён; исходные аккаунты сохранены. Автоматического CI
пока нет. Установка на физический iPhone и выполнение CMD-обёрток на Windows
в этой macOS-сессии не проверялись.
