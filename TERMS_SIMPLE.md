# Словарь для защиты простыми словами

- **Flutter** — набор инструментов, с помощью которого я делаю экраны мобильного приложения.
- **Dart** — язык, на котором написана мобильная часть моего проекта.
- **Rust** — язык, на котором написан сервер.
- **Клиент** — приложение на телефоне: показывает историю и отправляет запросы.
- **Сервер** — отдельная программа, которая проверяет запросы и работает с базой.
- **База данных** — место, где сохраняются пользователи, история, прогресс, картинки и покупки.
- **SurrealDB** — выбранная мной система для хранения этих данных.
- **SurrealDB Studio** — окно для просмотра и изменения базы; само по себе оно не запускает сервер БД.
- **Namespace и database** — два уровня, по которым я выбираю нужную базу: у проекта romance_club и main.
- **Таблица** — группа однотипных записей, например scene со сценами или player с игроками.
- **Запись** — один объект в таблице, например конкретная сцена.
- **Record ID** — адрес записи в SurrealDB: scene:228 означает сцену с номером 228; строка с таким текстом и настоящий адрес записи — разные типы данных.
- **Миграция** — пронумерованный файл, который обновляет устройство базы или переносит данные; это инструкция изменения базы, а не её резервная копия.
- **Журнал миграций** — список обновлений, которые база уже выполнила, чтобы не запускать их снова.
- **Контрольная сумма** — отпечаток содержимого файла: если изменить применённую миграцию даже по оформлению, сервер может заметить несовпадение.
- **Резервная копия** — отдельно сохранённые данные, из которых можно восстановиться при ошибке.
- **gRPC** — способ, которым приложение вызывает функции сервера: например просит загрузить эпизод или сохранить прогресс.
- **RPC** — один такой удалённый вызов функции.
- **Protobuf** — описание сообщений для обмена между приложением и сервером и способ компактно передавать их.
- **Файлы .proto** — договор, какие поля и запросы понимают обе стороны; по нему создаётся часть служебного кода.
- **API** — набор операций, которые одна программа предоставляет другой.
- **Асинхронная операция** — действие, результат которого придёт позже, например ответ сервера; интерфейс не должен на это время зависать.
- **Future и await** — в Dart это будущий результат и ожидание его получения.
- **JWT-токен** — подписанное сервером подтверждение входа; приложение прикладывает его к защищённым запросам.
- **Авторизация** — проверка разрешений: например может ли этот игрок менять историю.
- **Аутентификация** — проверка того, кто отправил запрос; обычно начинается со входа в аккаунт.
- **Хеш пароля** — проверочное значение вместо хранения самого пароля; Argon2 помогает безопасно его вычислить.
- **Транзакция** — несколько изменений базы как одно целое: либо проходят все, либо ни одно; например списание алмазов вместе с выдачей покупки.
- **Атомарность** — изменение не остаётся выполненным наполовину.
- **Откат** — отмена изменений неудачной транзакции.
- **Гонка запросов** — два действия выполняются одновременно и могут помешать друг другу, например дважды списать баланс.
- **Повторобезопасная операция** — повтор того же запроса не создаёт вторую покупку и не списывает деньги снова.
- **Ревизия** — номер версии сохранения: помогает не перезаписать новое состояние старым запросом.
- **Поколение сброса** — номер, который меняется после полного сброса и не позволяет старым запросам вернуть прежний прогресс.
- **Deadline / таймаут** — предел ожидания ответа сервера, после которого приложение сообщает об ошибке.
- **Кэш** — временно сохранённые данные, чтобы не скачивать или не обрабатывать их повторно.
- **Ассет** — ресурс приложения: картинка, музыка или звук.
- **Превью** — маленькая версия картинки для списка или сетки.
- **Alpha-канал** — прозрачность изображения: благодаря ей вокруг персонажа нет сплошного прямоугольника.
- **Баллы / счётчик** — числовое значение, например отношения с Лукой.
- **Флаг** — отметка «да/нет», например помогла ли я дедушке.
- **Условие** — правило, которое решает, доступна ли сцена: например отношения не ниже пяти баллов.
- **Граф сцен** — сцены и соединяющие их переходы; история может ветвиться, а не идти только по списку.
- **ViewModel** — часть кода, которая хранит состояние игры и её логику отдельно от оформления экрана.
- **Репозиторий** — промежуточный слой получения и сохранения данных, чтобы экран не зависел напрямую от сетевого запроса.
- **Жизненный цикл экрана** — его создание, показ и закрытие; ответ сервера после закрытия не должен менять уничтоженный экран.
- **Тест** — автоматическая проверка конкретного поведения; набор тестов не гарантирует отсутствие вообще всех ошибок.
- **Анализатор** — инструмент, который проверяет код без полного прохождения приложения.
- **Интеграционный тест** — проверка совместной работы нескольких частей или приложения на устройстве.
- **Эмулятор** — виртуальный Android-телефон на компьютере.
- **APK** — установочный файл Android-приложения.
- **Debug и release** — сборка для разработки и сборка для использования; release сама по себе не означает готовность к публикации в магазине.
- **Git** — система хранения истории изменений проекта.
- **Коммит** — сохранённый в Git набор изменений с подписью.
- **Issue** — отдельное замечание или задача в GitHub; исправленный код и закрытая карточка issue — не одно и то же.
- **SKU** — постоянный идентификатор товара, например конкретного платного выбора.
- **Хост и порт** — адрес компьютера и номер службы на нём.
- **adb reverse** — проброс порта по USB, чтобы телефон мог обратиться к серверу на подключённом компьютере.

## Как объяснить проект одной фразой

Я сделала приложение на Flutter, которое общается с Rust-сервером через gRPC, а сервер хранит историю, прогресс и покупки в SurrealDB.
