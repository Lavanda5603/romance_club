## Дополнительные исправления

- Удалены неиспользуемые прямой клиент SurrealDB и HTTP API service из Flutter,
  зависимость `surrealdb` и учётные данные БД из клиентского кода.
- Все семь gRPC-сервисов используют `GrpcConfig`: `GRPC_HOST`, `GRPC_PORT`,
  `GRPC_TLS`. По умолчанию `localhost:50051`; адрес эмулятора больше не зашит.
  USB с `adb reverse`, Wi-Fi и удалённый TLS endpoint описаны в README.
- Добавлены разрешение локальной сети iOS и исходящих соединений macOS.
- Адрес прослушивания сервера и подключение БД задаются окружением.
  По умолчанию gRPC слушает loopback; пароль БД обязателен.
- Rust SDK закреплён на SurrealDB `4.0.0`, используется стабильный Rust ≥1.95.
  Для compatibility level 4 добавлено явное заполнение новых обязательных полей
  и сужение типов bytes; перенос прогресса и создание индекса разделены.
  Конфликты записи с фоновой обработкой схемы повторяют целую атомарную
  транзакцию не более восьми раз с задержкой; остальные SQL-ошибки не скрываются.
- Проверка миграций дополнена заполненной старой схемой: сохранность аккаунта,
  счётчиков, флагов, связей и байтов оригинала проверяется после переноса
  и повторных запусков.

## Границы готовности

Проверка качества тестов выявила пробел в проверке TLS: замена `GrpcConfig.tls`
на постоянное `false` проходила исходные три теста даже с `GRPC_TLS=true`.
Ожидание исправлено: режим канала сравнивается напрямую с параметром сборки.
На той же намеренной поломке усиленный тест завершается ошибкой.

Автоматического CI в репозитории пока нет. Обычный `cargo test` пропускает
10 интеграционных тестов; их нужно явно запускать с отдельной SurrealDB.
Нет общего end-to-end теста Flutter → Rust → SurrealDB и проверки TLS handshake.
Большие Rust-сценарии стоит разделить: первая ошибка сейчас прерывает остальные
проверки внутри того же теста. Число успешных тестов не измеряет полноту покрытия.

Телефон, эмулятор, iOS/macOS release-сборки и публичный TLS-прокси в этой
проверке не запускались. Flutter Web требует отдельного gRPC-Web транспорта.
Адрес публичного сервера и его развёртывание остаются настройкой окружения.

Перед применением к реальной БД требуется проверенный backup. Изменённые файлы
миграций рассчитаны на переход с исходного `main`; если база уже содержит
журнал миграций от другой ветки, сначала проверьте переход на её копии.
Проверку checksum отключать нельзя: сервер намеренно останавливается при
несовпадении уже применённой миграции.

Обновление файлового хранилища SurrealDB 3 → 4 необратимо; следуйте
[инструкции SurrealDB](https://surrealdb.com/docs/build/migrating/from-old-surrealdb-versions/3x-to-4x).
Эта работа не меняла формат или содержимое пользовательского хранилища.
